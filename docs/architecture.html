Factory Inventory Management System

Architecture overview of a full-stack demo app: a Vue 3 single-page app talking to a Python FastAPI service that serves in-memory mock data loaded from JSON files. There is no database.

System Architecture

Three layers on one machine: a browser SPA, a stateless REST API, and static JSON files read once into memory when the server starts.

Data Flow: Changing a Filter

The four global filters drive almost every view. This is the path from a dropdown change to a re-rendered chart.

  1. User picks a filter in FilterBar

    Time Period, Warehouse, Category or Order Status. Values are written to module-level refs in useFilters.js. Because the refs live outside the function, every component shares one copy of the filter state.

  2. View reacts and requests data

    The active view watches the filter refs and calls getCurrentFilters(), which renames Time Period to month for the API.

  3. api.js builds the request

    Every filter left at "all" is dropped. The rest become query params, e.g. GET /api/orders?warehouse=Tokyo&month=2025-03.

  4. FastAPI filters in memory

    apply_filters() matches warehouse exactly and category / status case-insensitively. filter_by_month() does a substring match on order_date, and expands Q1-Q4 to three months.

  5. Pydantic validates the response

    Endpoints with a response_model serialise through Pydantic. Aggregate endpoints (dashboard, spending, reports) return plain dicts.

  6. Vue stores the result and re-renders

    Raw responses go into refs (allOrders, inventoryItems). Totals, chart series and tables are computed properties, so they update automatically.

Observations

Things found while reading the code that are worth knowing before you change it.

Frontend calls endpoints the backend does not have api.js defines /api/tasks (GET, POST, DELETE, PATCH) and /api/purchase-orders (GET, POST). main.py has no such routes, so the Tasks modal in App.vue gets 404s. There is a CreatePurchaseOrderRequest model, but no route uses it.
Reports bypasses the API client Reports.vue calls axios directly with a hardcoded http://localhost:8001 URL instead of going through api.js.
Orphaned view views/Backlog.vue exists but is not registered in the router. Backlog data shows up on the Dashboard instead.
Hardcoded config The API base URL in api.js and CORS allow_origins=["*"] in main.py are hardcoded. That is fine for a local demo but would need changing before any deployment.
